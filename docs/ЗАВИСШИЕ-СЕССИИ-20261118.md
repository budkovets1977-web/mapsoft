# Зависшие сеансы: причина, исправление, проверка

Дата: 18.11.2026
Стенд: `http://172.17.4.200:8080/` (МАПСОФТ MIS, MapWebServer)
Цель: не допускать зависших сеансов, освобождать лицензионные места.

## Кратко

Место освобождается только когда сеанс удаляется из хранилища (Redis).
Удаление возможно ровно в четырёх местах — и три из них не работали:

| механизм | кто вызывает | было | стало |
|---|---|---|---|
| `Cache::sessionDestroy()` | приложение при закрытии (`destroyMessage`, `uniquesession`) | работает | работает |
| `vacuumSessions()` | `common_assist::changeApp()` | не запускается (тип параметра) | вызывается, ошибка типа снята |
| `Cache::garbageCollectionSessions()` | клиент, раз в 15 мин | не удаляет (24 ч) | удаляет по `appTimeout` и «мёртвые» сеансы, раз в минуту |
| TTL записи сеанса в Redis | Redis | 24 ч | `appTimeout` + сообщение + 60 с |

## Что найдено на стенде (замеры 18.11.2026, 19:20–20:40)

- `getAccessTimeSessions` отдавал от 10 до 20 сеансов; все 18 из 20 были моими же
  вкладками с одного браузера.
- Через 10 минут после закрытия вкладок в списке осталось 12 «мёртвых» сеансов.
- Признак «мёртвого»: `ping` (`common/assist`) отвечает `Сессия уже закрыта` или
  `Undefined array key "mainService"`.

## Причины

1. `session.php` объявлял `vacuumSessions(array $params)`, а front-controller передаёт
   `stdClass` — `Argument #1 ($params) must be of type array, stdClass given`.
2. `cache.php` ждал истечения `SESSION_EXPIRE_TIME = 24 * 60 * 60`, игнорируя
   `appTimeout`; клиенту при этом отдавался `timeout` 970 с.
3. `timeout` в `cfg/config.json` у `mis` и `infopanel` (800) не применялся:
   `setupTimeout()` берёт `appTimeout` из `settings_app.json`.

## Внесённые правки (18.11.2026)

- `src/service/util/session.php`: `vacuumSessions(mixed $params)` + `(array)$params`;
  `getAccessTimeSessions()` отдаёт `Cache::sessionExpireTime()`.
- `src/service/util/cache.php`: `SESSION_EXPIRE_MARGIN = 60`, `GC_INTERVAL = 60`,
  `sessionExpireTime()`, `isSessionAlive()`; GC сравнивает `accessTime` с
  `appTimeout` и удаляет сеансы, у которых нет живой записи в Redis.
- `src/service/app/common/assist.php`: GC вызывается на каждом `changeApp`,
  присвоение `$params->sessions` убрано (ошибка на массивах).
- `src/service/app/pmed/insurance/common/login.php`: после успешного входа сеанс
  перевыпускается (`destroy` + новый id), старый id возвращается как `session` —
  после «Программа остановлена» клиент подхватывает новый без ошибок.
- `cfg/settings_app.json`: `appTimeout` 900 → 300.

Все файлы проверены `php -l`. Служба перезапущена.

## Проверка после правок

- Вход в систему — успешно.
- `vacuumSessions` с `params:{}` (объект) отрабатывает без ошибки
  (`Argument #1 must be of type array, stdClass given` больше не появляется).
- Очистка всех сеансов (9 зависших) через `vacuumSessions`:
  до 9, после 0.
- `login` после закрытия сеанса (продолжение, перезапуск, принудительно) —
  без `fatalError`.

## Что осталось

- `vacuumSessions` удаляет сеанс только на следующем обращении (отметка
  `destroyMessage`) — запись в Redis остаётся до GC. Перед включением автоочистки
  по «мёртвости» это нужно проверять отдельно.
- Пока сеансы администратора переживают остановку, новое поведение GC на них
  не вызвать: запись жива, хотя клиент считает её закрытой.
- `timeout` в `config.json` по-прежнему декоративный; если его нужно применять —
  отдельная правка в `setupTimeout()` (нужна пересборка клиента).

## Как закрыть зависшие сеансы руками

```powershell
$sid = '<сеанс администратора>'
$b   = '{"jsonrpc":"2.0","id":1,"method":"getAccessTimeSessions","params":{}}'
$r   = (Invoke-WebRequest "http://172.17.4.200:8080/service/common/main?session=$sid&config=mis" -Method POST -Headers @{'Content-Type'='application/json'} -Body $b).Content | ConvertFrom-Json
foreach ($i in $r.result.PSObject.Properties.Name | ? { $_ -notin @('timeout','currentTime') -and $_ -ne $sid }) {
  $p = '{"jsonrpc":"2.0","id":1,"method":"vacuumSessions","params":{"' + $i + '":{"id":"' + $i + '","message":"Сеанс завершён администратором"}}}'
  Invoke-WebRequest "http://172.17.4.200:8080/service/common/main?session=$sid&config=mis" -Method POST -Headers @{'Content-Type'='application/json'} -Body $p | Out-Null
}
```

Параметры `vacuumSessions` — **объект** `{id: {id, message}}`, не массив.
