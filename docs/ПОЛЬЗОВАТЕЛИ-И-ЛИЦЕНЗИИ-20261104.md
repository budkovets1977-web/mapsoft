2. Код сервисов (`common/login.php`, `map/common/login.php`,

   `map.sysinfo` — 141 запись, значения зашифрованы (не читаются).
   `map.syssetup` — только версии БД и настройки талонов.
4. `MapWebServer\crt\` — четыре файла ключей `*.mky` и запрос `WebAuth.mrq`
   (подробный разбор — п. 3.1). Содержимое ключей зашифровано, читаемых строк
   (список задач, число мест, даты) нет.
5. Файлов лицензий/ключей на диске сервера нет (поиск по `D:\Mapsoft` до глубины 2
   дал только `pgAdmin 4\LICENSE`).
6. Реестр сервера удалённо не читается (RemoteRegistry недоступен).

**Вывод.** Веб-сервер лицензируется регистрационным ключом `WebAuth.mky`, который
разрешает **набор задач (модулей)**, а не количество рабочих мест. Ни в конфиге,
ни в коде, ни в БД нет счётчика/лимита пользователей или одновременных сессий.
Число учётных записей технически не ограничено; ограничение — ресурсы сервера.
Если в ключе всё же зашито число рабочих мест, из сервера его не прочитать —
точную цифру можно взять только из документа на поставку, из настольного МАП
(«Администрирование → Регистрация / Электронные ключи») или у вендора МАПСОФТ.

## 3.1. Регистрационные ключи WebAuth (`.mky`) — разбор 04.11.2026

### 3.1.1. Как это работает по документации вендора

`MapWebServer\!readme.txt`, раздел «РЕГИСТРАЦИЯ»:

1. после запуска сервера при первом открытии формы входа выдаётся требование
   регистрации программы, и только тогда в `MapWebServer\crt` создаётся файл
   запроса `WebAuth.mrq`;
2. `WebAuth.mrq` передаётся в техподдержку МАПСОФТ, оттуда приходит файл-ключ
   с расширением `.mky`;
3. ключ кладётся в `MapWebServer\crt` и сервер перезапускается (`restart.bat`);
4. после перезапуска ключ разрешает доступ к нужным задачам.

`bin\setup.bat` при первичной установке просто переносит `bin\tools\auth\*.mky`
и `*.mrq` в `crt\`. Проверку ключей выполняет служба `MapWebAssist`
(`bin\tools\webassist\webassist.exe`), она ищет в `crt` файлы по маске `*.mky`
и по запросу PHP-сервера (`readTasks`) возвращает список разрешённых задач.
Это же подтверждают строки внутри `webassist.exe`: `TGDRegistrationForm`,
`tabLicense`, `richLicense`, `btnLicenseRequest`, `*.mrq`, `*.mky`,
«задача отсутствует в ключе активации», «требуемая функция отсутствует в ключе
активации», «закончен период действия программы/компьютера».

### 3.1.3. Формат файла

* текст: строки по 80 hex-символов, разделитель CRLF, без BOM, последняя
  строка короче; после hex-декодирования — 5 439–5 542 байта;
* энтропия 7,96 бит/байт (случайные данные), доля печатных символов ~36 %,
  как у случайного потока; сигнатур `PK`, `gzip`, `zlib`, ASN.1 нет;
* ни список задач, ни даты, ни число мест, ни серийный номер в открытом виде
  не присутствуют — тело зашифровано и подписано, разбор возможен только
  средствами МАПСОФТ (`webassist.exe` использует библиотеку DEC);
* у ключей `10-03mky` и `11-21mky` совпадают первые 16 байт
  (`a9d691642bbd9b528eb8c229316a4032`), остальное различается — общий
  идентификатор выпуска (тот же сервер/запрос), уникальное тело у каждого;
* первые 16 байт напрямую не совпадают ни с MD5/SHA1/SHA256 файла `WebAuth.mrq`,
  ни с его текстовой формой, т.е. привязка выполняется не «в лоб» хешем MRQ.

  покрывает весь комплект;
* ни в журнале, ни в `cfg\`, ни в БД нет ни числа рабочих мест, ни лимита

### 3.1.5. Выводы по ключам

1. Присланный файл `2026-07-03_11-21mky` — **не новый и не запасной ключ**,
   а копия ключа от 03.07.2026 11:46 с потерянной точкой в имени: служба
   `MapWebAssist` такие файлы не видит (маска `*.mky`), поэтому он лежит
   мёртвым грузом. Рабочий — только `2026-07-03_11-21.mky` (19.10.2026).
2. Ключ — это активация **задач/функций** для конкретного экземпляра сервера,
   а не лицензия на количество пользователей.
3. Ключ привязан к технической информации сервера, для которого сформирован
   `WebAuth.mrq`, поэтому **на другой сервер его переносить нельзя** — там
   нужно сформировать свой `WebAuth.mrq` (открыть форму входа до регистрации)
   и получить свой `.mky` у МАПСОФТ.
4. Сроки действия (программа/компьютер/задачи) зашиты внутри ключа и снаружи
   не читаются; при истечении `webassist.exe` вернёт «закончен период действия
   программы/компьютера» и задачи пропадут из `readTasks`.

## 4. Рекомендации

1. Назначить задачи 111 активным учёткам (или отключить лишние) — иначе люди
   входят и не могут работать.
2. Почистить 13 отключённых учёток с задачами и дубль #1.
3. Для точного числа лицензий — запросить у МАПСОФТ документ/письмо по ключу
   `WebAuth.mky` либо посмотреть в настольном МАП на сервере.
4. При необходимости посчитать текущие одновременные сессии — скрипт нужно
   запустить на самом сервере (Redis слушает только localhost).
