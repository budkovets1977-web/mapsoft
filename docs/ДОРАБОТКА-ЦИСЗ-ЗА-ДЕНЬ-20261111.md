# Доработка интерфейса МИС: «Отправить в ЦИСЗ за день»

**Версия: 6.00.60 · Дата: 11.11.2026 · Локальная разработка (не развёрнуто на боевом)**

Функциональная доработка: кнопка в главном меню → окно со списком неотправленных
посещений/дневников за дату → выбор галочками → массовая отправка в ЦИСЗ.

---

## Что реализовано

### 1. Бэкенд — новый класс `med_cisz_sendByDate`

**Файл:** `src/service/app/med/cisz/sendByDate.php` (отдельный, НЕ изменяет вендорский
`bundle.php`/`api.php`). Переиспользует штатный `med_cisz_bundle::createBundleAndImport()`.

Методы (JSON-RPC, роут `service/med/cisz/sendByDate` → `sendByDate.php`):

| Метод | Вход | Выход |
|---|---|---|
| `readUnsentByDate` | `{date: 'YYYY-MM-DD'}` | `{items: [{entity, id, patientId, date, patientName, doctorName, type}]}` |
| `sendSelected` | `{items: [{entity, id, patientId}]}` | `{results: [{entity, id, ok, message}]}` |

Логика «не отправлено»: в таблице `CiszLink` нет строки с `TableName` =
`MedVisitPatient`/`MedLogSend`, `PrimaryKey` = id и `Status = 1` (Sent).

Сущности:
- **Посещение** = `MedVisitPatient` (id = `MedVisitPatientCode`, дата — `MedVisit.VisitDate`).
- **Направление (дневник)** = `MedLogSend` (id = `MedLogSendCode`, дата — `DocumentDate`).

### 2. Фронтенд — новый модуль (view + controller + model)

Классы добавлены в существующие минифицированные файлы (все 3 темы: comfort/maptheme/maptouch):

- `Med.cisz.model.SendByDate` — в `app/med/cisz-model.js` (proxy `jsonrpc`, `readUnsentByDate`,
  `reader.rootProperty:'items'`).
- `Med.cisz.controller.SendByDate` — в `app/med/cisz.js` (методы `doLoad`, `onSendClick`).
- `Med.cisz.view.SendByDate` — в `app/med/cisz.js` (модальная форма `Common.view.Form`).

**Интерфейс окна:**
- Поле «Дата» (datefield, по умолчанию сегодня) + кнопка «Обновить».
- Грид с чекбоксами (`checkboxmodel`): колонки Тип / № / Пациент / Врач / Дата.
- Кнопка «Отправка» (активна, когда есть выбранные записи).

**Отправка:** `onSendClick` собирает отмеченные строки → JSON-RPC
`med/cisz/sendByDate/sendSelected` → показывает результат (отправлено/ошибки) → перезагружает список.

Открытие окна (из любого места, включая меню/навигатор):
```js
Ext.createFormModal('med-cisz-sendbydate', {args:{date:'2026-11-11'}})
// либо по алиасу виджета: Ext.widget('med-cisz-sendbydate')
```

## Что осталось: пункт в главном меню (навигаторе)

Навигатор приложения `med` (и всех под-задач `medcard`, `medreception` и т.д.) строится **из БД** —
метод `map_common_main::readNavigatorItems()` читает `FN_webGetNVItems(:task)` → таблицу **`SysMenu`**:

```sql
select
    SysMenuCode "id", SysMenuParentCode "parentId",
    Name "name", ModuleFileName widget, State state,
    Args args, ExData "exData"
from FN_webGetNVItems(:task)
where ModuleFileName is null or fn_WebUserAccess(Permission, :userId) = 1 ...
```

То есть пункт меню = строка в `SysMenu` со следующими значимыми полями:
- `Name` = «Отправить в ЦИСЗ за день»
- `ModuleFileName` = `med-cisz-sendbydate` (алиас виджета)
- `Args` = JSON `{"iconCls":"x-fa fa-paper-plane-o"}` (опционально)
- `SysMenuParentCode` = родительский пункт (корневой/нужный раздел)
- `Permission` = право доступа (как у существующих пунктов ЦИСЗ)
- `Level`, `Pos` — порядок отображения

**Точная структура `SysMenu` и значения `Permission` находятся в БД** (в исходниках PHP их нет).
Поэтому добавление пункта выполняется SQL-скриптом на сервере. Скрипт-заготовка — ниже
(требует уточнения имени таблицы/колонок и значения Permission под конкретную инсталляцию).

### SQL-заготовка (требует проверки на реальной БД)

```sql
-- Добавить пункт меню «Отправить в ЦИСЗ за день» (виджет med-cisz-sendbydate)
-- ВАЖНО: сверить реальные имена колонок SysMenu и допустимое Permission.
INSERT INTO SysMenu (
    SysMenuCode, SysMenuParentCode, Name, ModuleFileName, State, Args,
    Permission, Level, Pos
) VALUES (
    <новый SysMenuCode>, <parentCode>, 'Отправить в ЦИСЗ за день',
    'med-cisz-sendbydate', 1,
    '{"iconCls":"x-fa fa-paper-plane-o"}',
    '<permission как у соседних пунктов>', <level>, <pos>
);
```

## Проверка (локальная, без боевого сервера)

1. PHP-синтаксис бэкенда: `php -l .../sendByDate.php` — OK.
2. JS-баланс скобок/кавычек: append-блоки сбалансированы (сверено калиброванным чекером против
   эталона deploy-r6; дельты скобок/кавычек чётные).

Для полной проверки UI нужен запущенный фронтенд (браузер), что на локальной машине
возможно только при развёрнутом Apache+БД.

## Ограничения / риски

1. **Правка минифицированного ExtJS** (`cisz.js`, `cisz-model.js`) — внесена через
   добавление в конец файла (не трогая существующий код). При сборке новой версии правки
   нужно переносить так же (append-блоки).
2. **Пункт меню** — в БД (`SysMenu`); скрипт требует уточнения структуры под инсталляцию.
3. **Авторизация ЦИСЗ** — при отправке используется токен из текущей сессии пользователя
   (как и при штатной отправке из карточки). Если токена нет, `createBundleAndImport`
   вернёт ошибку — потребуется вход в ЦИСЗ (штатный механизм).
4. Отправка идёт по одному пакету на запись (не батч), как и в штатном UI.
