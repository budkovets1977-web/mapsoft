Структура передачи сообщений внутри расширения и между ними

{
	method: <method_name>,
	detail: {
		...
		<params>

}

схемы работы:

1. открытие файла - по клику на ссылку в веб приложении отсылается сообщение на скрипт контента расширения, которое
перенаправляется на бэкгрануд скрипт расширения, в котором создается стандартными средствами новая вкладка с указанной
ссылкой и открывается средствами барузера (на просмотр, либо скачивание)

2. информация по файлу - после загрузки документов, достаются записи из стора в массив, в процессе прохода по которому
формируется объект создержащий в ключе директорию, а в значении массив файлов в этой директории. После чего они
отправляются сообщение на скрипт контента расширения, который перенаправляет их на бэкграунд скрипт расширения.
Далее сообщение перенаправляется на бэкграунд скрипт iframe.js, в котром обрабатываются параметры и формируется url
строка HTTP запроса, которая открывается в отдельном iframe на фоновой странице. Как только страница загрузилась
парсятся переданные параметры из URL запроса и ищется в загруженном документе строки с информацией по переданным файлам.
После чего отправляется на бэкграунд скрипт, который сначала отправляет сообщение на удаление фрейма в iframe.js
(работает асинхронно), а затем передает информацию по файлам в скрипт контента, который в свою очередь передает ее
в веб приложение. В приложении обрабатываются сообщения от расширения, ищется запись с файлом и апдейтится информация.

3. выбор файла - по клику из веб приложения в расширение в скрипт контента передается сообщение, которое
перенаправляется в бэкграунд скрипт. Далее отправляется сообщение по ID в бэкграунд скрипт приложения, в котром
создается невидимое окно для возможности запуска из скрипт контента этого окна диалога выбора файлов, а так же
взятия полного пути до выбранного файла. После выбора файла отправляется сообщение в бэкграунд скрипт расширения,
который сначала вызывает функцию добычи информации по файлу из п.2(работает асинхронно), а затем передает сообщение в
скрипт контента, он уже в свою очередь шлет сообщение в веб приложение, где добавляется новая запись в стор с
переданным путем, и подгружается информация по файлу из п.2
